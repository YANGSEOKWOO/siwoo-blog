# 새 글 작성

Siwoo의 블로그(Astro)에 새 글을 **초안(draft: true)** 으로 만들고, 사용자가 준 메모·주제를 바탕으로 함께 작성한다.
글은 사용자의 글이다. 사용자의 생각과 경험을 정리해 주는 역할이며, 사용자가 말하지 않은 경험·수치·사실을 지어내지 않는다.

입력: `$ARGUMENTS` (예: `tech Redis 캐시 스탬피드 겪은 썰`, `book 데이터 중심 애플리케이션 설계`)

## 1. 정보 모으기

`$ARGUMENTS`에서 아래를 추출하고, 빠진 것만 한 번에 묻는다 (AskUserQuestion, 질문 최대 2개).

- **카테고리**: `tech`(기술) 또는 `book`(책)
- **주제/제목**: 무엇에 대한 글인지
- **재료**: 사용자가 가진 메모, 코드, 로그, 밑줄 친 문장 등. 없으면 "개요만 잡을지 / 대화하며 같이 채울지" 확인한다.
- 책이면: 책 제목, 저자 (출판사·연도는 선택)

## 2. 초안 파일 만들기

1. 주제를 영어 kebab-case **slug**로 만든다 (짧고 검색 친화적으로, 예: `redis-cache-stampede`, `book-ddia`). slug는 URL이 되므로 나중에 바꾸지 않는다.
2. 다이어그램 컴포넌트(ServerFlow)를 쓸 글이면 `--mdx`를 붙인다. 서버 간 통신·요청 흐름을 설명하는 기술 글이면 기본적으로 mdx를 고려한다.
3. 스크립트로 생성한다 (직접 파일을 새로 쓰지 말 것 — frontmatter 형식이 스크립트에 맞춰져 있음):

```bash
npm run new -- <tech|book> <slug> "<제목>" [--mdx]
```

## 3. 본문 작성

생성된 `src/content/blog/<slug>.md(x)`를 열어 채운다.

**frontmatter**
- `description`: 검색 결과와 공유 카드에 그대로 노출된다. 글의 핵심을 80~120자 한국어 한 문장으로. "~에 대해 알아봅니다" 같은 빈 문장 금지.
- `tags`: 소문자 영어 또는 한국어 2~4개 (예: `['redis', 'cache']`). 기존 글의 태그를 `grep -h "^tags:" src/content/blog/*` 로 확인하고 같은 표기를 재사용한다.
- 책이면 `book.title`, `book.author` 채우기.
- `draft: true`는 그대로 둔다 (발행은 `/publish-post`).

**본문 원칙**
- 문체는 **합니다체**(~습니다, ~입니다, ~할까요?). `~한다/~했다` 평서체는 쓰지 않는다 (사용자가 "AI스럽다"고 함).
- 사용자가 직접 쓴 문장은 거의 그대로 살리고(맞춤법 정도만), 고친 곳은 알려준다.
- "왜 이 일을 하는지"를 먼저, 방법은 그 다음에.
- `##`(h2)가 목차가 된다. 섹션 3~6개, 제목은 내용을 요약하는 문장형으로 (예: "## 배경" 보다 "## 동시에 만료된 키가 DB를 때렸다").
- 첫 문단에서 이 글이 어떤 문제를 다루고 독자가 무엇을 얻는지 2~3문장으로 말한다.
- 사용자 재료에 없는 수치, 실험 결과, 회사 상황은 쓰지 않는다. 비어 있는 부분은 TODO 주석으로 표시하고 사용자에게 알려준다. `.md`는 `<!-- TODO: ... -->`, `.mdx`는 `{/* TODO: ... */}` (MDX에서 HTML 주석은 빌드 오류).
- 책 글: 요약보다 사용자의 생각과 적용점이 중심. 인용은 `>` 블록으로, 사용자가 준 문장만 인용한다.
- 기술 글: 재현 가능한 코드, 원인 → 해결 → 결과 순서.

사용할 수 있는 표현(코드 블록 옵션, Mermaid, 수식, ServerFlow 애니메이션 다이어그램)은 [reference.md](reference.md)를 참고한다.

**이미지**: `src/assets/posts/<slug>/`에 두고 상대 경로로 넣는다 → `![설명](../../assets/posts/<slug>/diagram.png)`. alt 텍스트는 반드시 쓴다.

## 4. 확인

1. `npx astro check` 로 frontmatter/타입 오류가 없는지 확인한다.
2. 개발 서버가 꺼져 있으면 `npx astro dev --background`로 켠다.
3. 사용자에게 미리보기 주소 `http://localhost:4321/blog/<slug>/`, 남은 TODO 목록, 발행 방법(`/publish-post <slug>`)을 알려준다.
