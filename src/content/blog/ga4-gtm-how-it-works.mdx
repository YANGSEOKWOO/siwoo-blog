개발을 하면서, 사용자들의 반응을 기반으로 측정가능한 지표를 먼저 구축해놓는다는 게 중요한 것 중에 하나임을 깨달았습니다.

그렇기에 이번 블로그를 만들면서, 해당 부분들에 대해 정리를 해보았습니다.

## 왜 사용자 지표를 측정해야 할까요?

웹사이트를 운영한다고 했을 때, 사용자가 어떤 페이지에 들어오고, 얼마나 머물고, 어디서 나가는지 같은 패턴을 분석해서 더 나은 서비스를 만들어 가는 것을 **웹 분석(Web Analytics)** 이라고 합니다.

그렇기에 구글에서는 GA4, GTM, Search Console 등을 통해 사용자의 활동 지표를 수집하고 볼 수 있는 도구를 제공하고 있습니다.

- **GA4 (Google Analytics 4)**: 사용자의 활동 기록을 받아서 저장하고, 보고서로 보여줍니다.
- **GTM (Google Tag Manager)**: 사이트에 어떤 측정 코드를 실행할지 관리합니다.
- **Search Console**: 구글 검색에서 내 사이트가 얼마나 노출되고 클릭되는지 보여줍니다.

## 세 도구는 어떻게 연결될까요?

세 도구는 사용자 여정에서 서로 다른 구간을 맡습니다. Search Console은 사용자가 **사이트에 들어오기 전**, GA4는 **들어온 후**를 봅니다. GTM은 데이터를 보여주는 도구가 아니라, GA4 같은 측정 코드를 사이트에 실어 나르는 **통로**입니다.

<AnalyticsMap caption="사용자 여정과 각 구간을 측정하는 도구" />

가장 큰 차이는 데이터 출처입니다. Search Console은 구글이 이미 가진 검색 데이터를 보여주기 때문에 사이트에 측정 코드가 없어도 동작합니다. 반대로 GA4는 사이트에 심은 코드가 보내는 데이터만 알기 때문에, 검색 결과 화면에서 무슨 일이 있었는지는 모릅니다.

세 도구는 이렇게 연결됩니다.

- **GTM → GA4**: GTM 컨테이너 안의 Google 태그가 브라우저에서 실행되면서 GA4로 기록을 보냅니다. 이 블로그가 지금 쓰고 있는 구성입니다.
- **Search Console ↔ GA4**: GA4의 **관리 → 제품 링크 → Search Console 링크**에서 두 서비스를 연결하면, "어떤 검색어로 들어온 사람이 글을 끝까지 읽었는지"처럼 방문 전과 후를 이어서 볼 수 있습니다.
- **GTM → Search Console**: 사이트에 GTM이 설치되어 있으면 Search Console의 소유권 확인 방법으로 GTM을 고를 수 있습니다. 데이터가 오가는 것은 아니고, 인증 수단으로만 쓰입니다.

참고로 Search Console의 클릭 수와 GA4의 검색 유입 세션 수는 보통 같지 않습니다. Search Console은 검색 결과에서 클릭한 순간을 세고, GA4는 방문자 브라우저에서 태그가 실행되어야 세기 때문입니다. 광고 차단기를 쓰거나 페이지가 뜨기 전에 나간 방문은 GA4에서 빠집니다.

## GA4와 GTM은 각각 무엇을 관리할까요?

### GA4

| 개념 | 설명 |
| --- | --- |
| 속성 | 사이트 하나의 데이터를 모아두는 공간입니다. 이 블로그 전용 속성을 따로 만들었습니다. |
| 데이터 스트림 | 데이터가 들어오는 통로입니다. 웹사이트 주소를 등록하면 **측정 ID(`G-...`)** 가 발급됩니다. |
| 향상된 측정 | 켜두면 스크롤, 외부 링크 클릭 같은 이벤트를 별도 설정 없이 자동으로 수집합니다. |
| 맞춤 측정기준 | 이벤트와 함께 보낸 값(예: 글 카테고리)을 보고서에서 나눠 보려면 미리 등록해야 합니다. 등록한 시점부터 집계됩니다. |

### GTM

| 개념 | 설명 |
| --- | --- |
| 컨테이너 | GTM이 구글 서버에 만들어 두는 자바스크립트 파일입니다. 사이트에는 이 파일을 불러오는 짧은 스크립트만 넣어 둡니다. **컨테이너 ID(`GTM-...`)** 로 구분합니다. |
| 태그 | 컨테이너 안에서 실행되는 코드 하나입니다. "GA4로 기록 보내기"가 태그 하나입니다. |
| 트리거 | 태그를 언제 실행할지 정합니다. 예를 들어 "모든 페이지가 열릴 때"입니다. |
| 게시 | 태그와 트리거를 바꾼 뒤 게시해야 실제 방문자에게 반영됩니다. |

GTM의 장점은 사이트 코드를 다시 배포하지 않고 측정 방식을 바꿀 수 있다는 점입니다. 사이트에는 컨테이너만 한 번 심어두고, 이후에 히트맵 같은 도구를 추가하고 싶으면 GTM에서 태그만 추가하면 됩니다.

이 블로그에서는 GTM 컨테이너에 **Google 태그(측정 ID `G-...`)** 하나를 넣고, 트리거를 **Initialization - All Pages**로 설정했습니다.

## 페이지 하나가 열릴 때 일어나는 일

	]}
/>

1. 방문자가 블로그 글 주소로 들어오면 Vercel이 HTML을 내려줍니다.
2. HTML 안의 짧은 스크립트가 `googletagmanager.com/gtm.js?id=GTM-...`에서 **컨테이너**를 내려받습니다. 컨테이너는 GTM에서 만든 태그와 트리거가 담긴 자바스크립트 파일입니다.
3. 컨테이너 안에는 "모든 페이지가 열릴 때 Google 태그(`G-...`)를 실행하라"는 설정이 들어 있습니다.
4. Google 태그가 실행되면서 브라우저가 GA4 수집 서버로 기록을 보냅니다. 페이지뷰(`page_view`)와 함께, 향상된 측정을 켜두었기 때문에 스크롤(`scroll`)과 외부 링크 클릭(`click`)도 자동으로 수집됩니다.
5. GA4가 이 기록을 모아 보고서를 만듭니다.

여기서 기록을 보내는 주체는 블로그 서버(Vercel)가 아니라 **방문자의 브라우저**입니다. 그래서 광고 차단기가 GA 요청을 막으면 그 방문은 집계되지 않습니다.

브라우저 개발자 도구(F12) → Network 탭에서 `collect`로 필터링하면 실제 요청을 볼 수 있습니다. 요청 주소에 붙은 값 중 `tid`는 측정 ID, `en`은 이벤트 이름, `dl`은 페이지 주소입니다.

## 정리

- 웹 분석은 사용자 행동을 숫자로 보고 서비스를 개선하는 일이고, GA4와 GTM은 그 도구입니다.
- Search Console은 방문 전(검색), GA4는 방문 후(사이트 안)를 보고, GTM은 측정 코드를 사이트에 실어 나릅니다.
- GA4는 데이터를 받아 보고서를 만들고, GTM은 사이트에서 어떤 측정 코드를 실행할지 관리합니다.
- 기록을 GA4로 보내는 주체는 방문자의 브라우저이고, 그 일을 하는 것이 GTM 컨테이너 안의 Google 태그입니다.
