```java
public synchronized void increment() {   // 메서드 전체를 잠금 (this의 자물쇠 사용)
    count++;
}

void increment() {
    synchronized (this) {                // 이 블록만 잠금
        count++;
    }
}
```

`synchronized void`라는 단어 하나가 있는 게 아닙니다. `public`, `static`처럼 메서드 앞에 붙는 **수식어**입니다. 다른 스레드는 앞 스레드가 블록을 나갈 때까지 문 앞에서 기다립니다.

**반납 체계가 언어에 정해져 있습니다**

`synchronized`는 라이브러리 함수가 아니라 `if`, `for` 같은 **언어 문법(키워드)** 입니다 ([언어 문법과 라이브러리](#term-syntax-vs-library)). 그래서 중괄호 `{ }`가 곧 잠금 구간이고, 컴파일러가 잠그기와 반납 코드를 알아서 넣습니다.

```text
monitorenter      ← { 에서 잠그기 (컴파일러가 넣음)
... count++ ...
monitorexit       ← } 에서 반납 (컴파일러가 넣음)
...
monitorexit       ← 예외가 나도 반납 (컴파일러가 넣음)
athrow
```

**보장해 주는 것과 아닌 것**

| 구분 | 내용 |
|---|---|
| 보장함 | 한 번에 한 스레드만 들어오기 + 블록 안에서 바꾼 값이 다음 스레드에게 보이기 |
| 보장함 | 잠갔으면 **반드시 반납** (예외가 나도) |
| 보장하지 않음 | **잠가야 할 곳을 다 잠갔는지** |

```java
synchronized void increment() { count++; }   // 잠금 O
void decrement() { count--; }                 // 잠금 깜빡함 → 컴파일러는 모름
```

반납은 언어가 책임지지만, 어디를 잠글지는 여전히 개발자 몫입니다. 참고로 `synchronized`를 쓴다고 매번 OS를 부르지는 않습니다. JVM이 먼저 가볍게 잠금을 시도하고, 다른 스레드와 정말 부딪혀서 기다려야 할 때만 OS의 도움을 받습니다.
