```java
Thread t = new Thread(() ->
    System.out.println("실행한 스레드: " + Thread.currentThread().getName()));

t.run();     // 출력: 실행한 스레드: main      ← 새 스레드가 안 생김
t.start();   // 출력: 실행한 스레드: Thread-0  ← 새 스레드에서 실행
```

**누가 스레드를 만들까요?**

정확히는 **기존 스레드가 요청하고, JVM이 준비하고, OS가 만듭니다.** `t.start()`를 실행하는 것은 main 스레드이고, 그 안에서 이런 일이 일어납니다.

1. **JVM**: 이 Thread 객체를 이미 시작한 적이 있는지 확인합니다 (두 번 `start()`하면 `IllegalThreadStateException`).
2. **JVM**: 새 스레드용 내부 자료구조를 준비합니다.
3. **JVM → OS**: "스레드 하나 만들어 줘"라고 요청합니다 (리눅스·맥 `pthread_create`, 윈도우 `CreateThread` 계열).
4. **OS**: 새 OS 스레드와 그 스레드 전용 스택(보통 1MB 안팎)을 만듭니다. 이것이 "시스템 자원 할당"입니다.
5. `start()`는 여기서 **바로 돌아오고**, main은 다음 줄로 진행합니다.
6. **새 스레드**는 JVM의 시작 루틴을 거쳐 `run()`을 호출하고, `run()`이 끝나면 종료되며 자원을 반납합니다.

그래서 "`start()`는 준비 작업을 마친 뒤 **새로운 스레드에서** `run()`을 호출한다"고 합니다. `run()`을 실행하는 주체가 main이 아니라 **새로 태어난 스레드**라는 뜻입니다.

| | `t.run()` | `t.start()` |
|---|---|---|
| 새 OS 스레드 생성 | X | O |
| 람다를 실행하는 스레드 | 호출한 스레드 (main) | 새 스레드 |
| 호출한 쪽은 | 람다가 끝날 때까지 기다림 | 바로 다음 줄로 진행 (동시에 실행) |

**fork와는 다릅니다**

| | `fork()` | `start()` |
|---|---|---|
| 새로 생기는 것 | **프로세스** (JVM이 통째로 하나 더) | 같은 프로세스 안의 **스레드** |
| 메모리 | 부모의 메모리를 **복사**해서 따로 가짐 | 기존 자바 힙을 **공유** |

리눅스에서는 둘 다 내부적으로 `clone()`이라는 같은 시스템 콜을 쓰고, "메모리를 복사하느냐 공유하느냐"를 옵션으로 정합니다. 그래서 "fork처럼 보이지만 메모리를 공유하는 버전"이라고 이해해도 됩니다.

**부모·자식 관계가 아닙니다**

프로세스는 부모·자식 관계가 뚜렷하지만, 자바 스레드는 만든 뒤에는 **서로 대등**합니다. main이 먼저 끝나도 새 스레드는 계속 돕니다. JVM은 **데몬이 아닌 스레드가 모두 끝나야** 종료됩니다.
