```java
ExecutorService executor = Executors.newFixedThreadPool(3);
```

- `ExecutorService`는 `java.util.concurrent` 패키지에 있는 **인터페이스**(약속)입니다. "태스크를 받아서 실행해 주는 것은 `submit()`, `shutdown()` 같은 메서드를 가진다"고 정해 둡니다.
- `Executors.newFixedThreadPool(3)`은 그 약속을 구현한 **실제 객체**(`ThreadPoolExecutor`)를 만들어 돌려줍니다.

그래서 ExecutorService도 결국 **힙에 있는 평범한 객체**입니다. 특별한 점은 이 객체가 **대기열과 일꾼 스레드 여러 개를 거느린 관리자**라는 것입니다.

**실행 흐름**

1. **만들기**: `newFixedThreadPool(3)` → 관리자 객체가 생깁니다. 일꾼 스레드는 태스크가 들어오는 대로 **최대 3개까지** 만들어집니다.
2. **제출하기**: `executor.submit(task)` → 호출한 스레드는 태스크를 대기열에 넣고 **바로 돌아옵니다.**
3. **실행하기**: 일꾼 스레드는 일 하나를 끝내고 죽는 게 아니라, 반복문을 돌며 **계속 다음 태스크를 꺼내 돌려씁니다.** 대기열이 비면 쉬면서 기다립니다.
4. **정리하기**: `shutdown()`(또는 try-with-resources의 `close()`) → 더 이상 제출을 받지 않고, 남은 일을 끝낸 뒤 일꾼 스레드들이 종료됩니다.

```java
try (ExecutorService executor = Executors.newFixedThreadPool(3)) {
    executor.submit(() -> sendMail());
    Future<Integer> f = executor.submit(() -> 1 + 1);
    System.out.println(f.get());   // 2
} // close()가 남은 태스크가 끝나길 기다린 뒤 정리 (Java 19+)
```

**"동시에 실행되는 스레드 수를 제어한다"**

일꾼이 3명뿐이라 태스크를 아무리 많이 제출해도 **한 순간에 실행되는 건 최대 3개**입니다. 나머지는 대기열에서 차례를 기다립니다.

<PoolVsThreads />

수를 제어하는 이유는 다음과 같습니다.

- **[플랫폼 스레드](#term-platform-thread)는 비쌉니다.** 하나당 OS 스레드와 스택(1MB 안팎)이 필요합니다. 요청이 1만 개 몰릴 때 스레드를 1만 개 만들면 메모리가 바닥나고 컨텍스트 스위칭만 늘어납니다.
- **상대방을 보호합니다.** DB가 동시 연결 50개까지만 받는다면, 일꾼을 50명으로 묶어 두면 그 이상 몰려가지 않습니다.
- **만들고 없애는 비용을 아낍니다.** 한 번 만든 스레드를 계속 돌려씁니다.

Spring Boot의 Tomcat 스레드 200개도 이런 스레드 풀입니다.

**이 책과의 연결**

```java
Executors.newFixedThreadPool(200)            // 플랫폼 스레드 200개를 돌려씀 → 동시 실행 최대 200
Executors.newVirtualThreadPerTaskExecutor()  // 태스크마다 가상 스레드를 새로 만듦 → 상한 없음
```

가상 스레드는 싸니까 **돌려쓸 필요도, 수를 묶어 둘 필요도 없습니다.** 그래서 "스레드 풀"이 아니라 **"태스크마다 하나씩"** 방식으로 씁니다. 그래도 DB 보호처럼 동시 실행 수를 제한해야 할 때는 스레드 수 대신 `Semaphore` 같은 도구로 제한합니다.
