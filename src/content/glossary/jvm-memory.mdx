헷갈리는 이유는 **프로그램이 두 개처럼 보이기 때문**입니다. OS 입장에서 실행된 프로그램은 **JVM 하나뿐**이고, 내 자바 프로그램(`Hello.class`)은 JVM이 읽어서 실행해 주는 **내용물**입니다.

- **JVM**은 진짜 프로그램이라, OS가 다른 프로그램처럼 코드·데이터·힙·스택 영역을 만들어 줍니다.
- **내 자바 프로그램**에는 OS가 영역을 따로 만들어 주지 않습니다. 대신 **JVM이 자기 메모리 안에 자바용 구역을 마련해서** 마치 독립된 프로그램처럼 돌아가게 해 줍니다.

| 내 자바 프로그램 입장 | 실제로 들어가는 곳 |
|---|---|
| 코드 | **메타스페이스**(바이트코드), **코드 캐시**(JIT가 번역한 기계어) |
| 데이터 (static 변수) | **자바 힙** (최신 JVM 기준) |
| 힙 (객체) | **자바 힙** |
| 스택 (메서드 호출, 지역 변수) | **스레드 스택** (JVM 자신의 함수 호출 기록과 같은 스택에 섞여 쌓임) |

**자바 힙 vs 네이티브 힙**

둘 다 "필요할 때 꺼내 쓰는 메모리"라서 이름이 같을 뿐, **서로 다른 구역**입니다. 자바 힙은 네이티브 힙 **안에** 있는 게 아니라 그 **옆에** 따로 있습니다.

| | 네이티브 힙 | 자바 힙 |
|---|---|---|
| 누가 관리하나 | `malloc` / `free` (C 런타임) | JVM + 가비지 컬렉터 |
| 무엇이 들어가나 | JVM 자신이 내부용으로 쓰는 데이터 | `new`로 만든 자바 객체 |
| 어떻게 받나 | 필요할 때 조금씩 | 시작할 때 OS에 직접 큰 구역을 요청 (윈도우 `VirtualAlloc`, 리눅스·맥 `mmap`) |
| 크기 설정 | 따로 정하지 않음 | `-Xmx`로 최대 크기 지정 |

자바 힙을 따로 받는 이유는 가비지 컬렉터 때문입니다. GC는 객체를 옮기고, 구역을 나누고, 빈 곳을 한꺼번에 정리해야 해서 **크고 연속된, 마음대로 배치할 수 있는 땅**이 필요합니다.

> 비유: 프로세스 메모리는 **아파트 단지**입니다. 네이티브 힙은 단지 안의 **공용 창고**이고, JVM은 창고에 칸막이를 친 게 아니라 관리사무소(OS)에서 **별도 부지를 통째로 분양받아** 자바 전용으로 씁니다.

자바 개발자가 "힙"이라고 하면 거의 항상 **자바 힙**을 말합니다. 여러 스레드가 함께 보는 곳도 여기입니다.
